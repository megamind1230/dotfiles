#+TITLE: baka's dotfiles

Personal configuration for an Arch Linux setup: dual Wayland (Hyprland) / X11 (i3) sessions, bash, Emacs, two Neovim configs, Helix, Zed, Kitty, mpv, plus a toolbox of shell scripts.

The repo mirrors =$HOME=: files get symlinked into place (=~/.bashrc=, =~/.config/*=, including =~/.config/emacs-profiles=). =~/scripts= is a symlink to this repo's =scripts/= directory and is added to =$PATH=, so every script here runs as a bare command from anywhere.

* Shell files
** =.profile=
*Why:* sourced by the display manager / login shell — sets the environment before Hyprland or i3 starts. Non-interactive counterpart of =.bashrc=.

Sections:
- *Exports* — =EDITOR=/=VISUAL==emacsclient -s emacs-profile-baka -c=, =BROWSER=helium-browser=, =TERMINAL=kitty=
- *PATH* — prepends =~/.opencode/bin=, =~/.local/bin=, =~/scripts/= (the symlink into this repo), =~/.dotnet/tools=; appends =/opt/nvim-linux-x86_64/bin=. (It also still lists =~/.config/emacs/bin= and =~/.emacs.d/bin= — both point at directories that no longer exist, leftover entries.)

Both files agree on =BROWSER=helium-browser= these days.

** =.bashrc=
*Why:* main bash config for interactive shells. It's an *orchestrator*: baseline settings, then sources the three extension files in order.

Sections:
1. *Interactivity guard* — returns immediately for non-interactive shells
2. *History* — no dupes / ignores space-prefixed commands, append mode, HISTSIZE=1000
3. *Shell options* — checkwinsize (globstar/lesspipe commented out)
4. *Environment* — opencode on PATH; =MANWIDTH=999= (the =MANPAGER='nvim +Man!'= line is commented out); EDITOR/VISUAL=emacsclient on the baka socket; BROWSER=helium-browser; TERMINAL=kitty; PATH prepends (.local/bin, doom emacs bin, scripts/, dotnet tools) plus a =DOOMDIR= export; recording defaults =SCREENREC_AUDIO_SINK= / =SCREENREC_AUDIO_SOURCE= consumed by the mic/screenrecording scripts
5. *Prompt* — color PS1 =user@host:cwd$=, sets xterm window title
6. *ls colors* — dircolors eval + basic =ls --color= alias (overridden later by -aliases)
7. *Completion* — sources bash-completion
8. *Source chain* — =.bashrc-personal= → =.bashrc-aliases= → =.bashrc-functions=; this order defines precedence

** =.bashrc-functions=
*Why:* functions, fzf integrations, readline keybindings, and the competitive-programming generator. Sourced last. Uses =# @desc= comments above definitions — parsed by the Alt+F picker as documentation.

Sections:

*** Package management
- =inst <pkgs>= sudo pacman -S; =pinst= paru (AUR); =search= / =psearch= query results printed bottom-up (=tac=)

*** Archives
- =ex <archive>= extracts by extension (tar, tar.gz/tgz, tar.bz2, tar.xz, zip, rar, 7z, gz, bz2)
- =compress <out> <src>= creates tar/tar.gz/tar.bz2/tar.xz/zip/7z by output extension

*** Script runner
- =scriptsRun= lists executable files in =~/scripts= with their first =# @desc= line, fzf-picks one, runs it
- *Alt+S* readline bind invokes it from the prompt

*** Emacs profiles (registry)
- =~/dotfiles/emacs-profiles= (symlinked as =~/.config/emacs-profiles=) is the single source of truth: one =label|name|server|init-dir|env= line per profile (baka, doom, vanilla). Adding a config = appending a line — no aliases or functions to write
- =emacs-profile <name> [args…]= launches a profile (starts its daemon first if needed); =ep= / =ep-doom= / =ep-vanilla= are thin shortcuts for the three real profiles
- =emacs-profile-entry <name>= prints one profile's registry line (used internally); =emacs-daemon-start <name>= starts a single daemon headlessly
- =ed= starts any daemon that isn't running (idempotent — safe on Hyprland reload, and what the Hyprland autostart hook calls); =emacs-daemons-restart= kills + restarts all three; =es= prints running/DOWN per profile plus the socket dir
- =scripts/emacs-app= is the same logic as a standalone script (registry lookup → named =--daemon=<server>= → wait up to 10s → =emacsclient -s <server> -c=, failures logged to =~/.cache/emacs-<server>.log=); used by =emacs-profile=, =editor-switcher=, and the cps =e= IDE

**** Adding a New Profile

*Emacs* — append one line to =~/dotfiles/emacs-profiles= (=label|name|server|init-dir|env=, =$HOME= expanded at parse time):

   #+begin_src bash
   my experiment|test|emacs-profile-test|$HOME/.config/emacs-profile-test|
   #+end_src

Then =emacs-profile test=, =Alt+E=, =ed= and =es= all know about it — nothing else to edit. The =server= field is the socket name =emacsclient -s= connects to, so it must be unique per profile. If the config needs env vars (like =DOOMDIR=), append them as the fifth field: =DOOMDIR=$HOME/…=.

*Neovim* — add one literal line to =editor-switcher= in =~/.bashrc-functions= (key = =NVIM_APPNAME=, empty key = default =~/.config/nvim/=):

   #+begin_src bash
   printf 'nvim|my label|MYKEY\n'
   #+end_src

Then reload: =source ~/.bashrc=.

**** How It Works

#+begin_example
 Alt+E ──> fzf picker ──> (type "nvim" / "emacs" to filter) ──> launch editor
                            │
                            ├── nvim:*  ──> NVIM_APPNAME=<key> nvim               (foreground)
                            └── emacs:* ──> setsid -f ~/scripts/emacs-app <name> (detached)
                                              </dev/null >/dev/null 2>~/.cache/editor-switcher.log
#+end_example

- =nvim:*= profiles launch via =NVIM_APPNAME= (empty key = default =~/.config/nvim/=, a key makes nvim read =~/.config/nvim-<key>/=) and stay *in the foreground* — a TUI needs the terminal, so =Alt+E= keeps it until nvim exits
- =emacs:*= profiles launch via =~/scripts/emacs-app=, which looks the name up in =~/.config/emacs-profiles=, exports that profile's env (e.g. =DOOMDIR=), starts its daemon with =--init-directory= + =--daemon=<server>= if the socket isn't answering (up to 10s, logged to =~/.cache/emacs-<server>.log=), then connects =emacsclient -s <server> -c=. Wrapped in =setsid -f=: own session, no controlling tty, no shell job entry — the prompt comes back immediately even while a cold daemon (doom) boots
- Nothing prints to the terminal, so the detached emacs launch sends =stderr= to =~/.cache/editor-switcher.log= — that file is where a failed profile shows up
- Escape or Ctrl+C cancels (the fzf picker itself is modal: it owns the tty while it is open)

**** Emacs-Doom Setup

Doom Emacs needs a two-directory structure:

#+begin_example
~/.config/emacs-doom/
├── emacs/     ← doom-emacs engine (cloned repo)
└── doom/      ← your custom config (DOOMDIR: config.el, init.el, packages.el)
#+end_example

1. *Clone doom-emacs*:
   #+begin_src bash
   git clone https://github.com/doomemacs/doomemacs ~/.config/emacs-doom/emacs
   #+end_src

2. *Set =DOOMDIR= and run the installer* (interactive, takes a while) — so doom uses =~/.config/emacs-doom/doom=, not the default =~/.config/doom=:
   #+begin_src bash
   export DOOMDIR="$HOME/.config/emacs-doom/doom"
   ~/.config/emacs-doom/emacs/bin/doom install
   #+end_src

3. *=DOOMDIR= is provided automatically*: the registry's doom line exports it before the daemon starts, so =ep-doom= and =Alt+E= just work. (It's also exported in =~/.bashrc= for the =doom= CLI/installer, which needs it outside Emacs.)

4. *Test it*: =ep-doom= or pick via =Alt+E=

The registry already sets =DOOMDIR= for the daemon at launch time, but the installer (=doom install=) also needs it in the environment — otherwise it creates =~/.config/doom/= and you end up with two separate doom configs.

The =~/.config/emacs-doom/emacs/bin= PATH entry is already exported in =~/.bashrc=, so the =doom= CLI works once cloned.

** =scripts/emacs-app= (+ =emacs-profiles= registry)
*Why:* the emacs launcher behind =e=, =ep*=, =Alt+E=, and the cps =e= IDE. Reads =~/.config/emacs-profiles= (=label|name|server|init-dir|env= per line), exports the profile's env (e.g. =DOOMDIR=), starts that profile's daemon with =--init-directory= + =--daemon=<server>= when its socket is dead (waits up to 10s, logs to =~/.cache/emacs-<server>.log=, fails loudly with the log path), then runs =emacsclient -s <server> -c=. To add a profile you edit the registry, not this script.
